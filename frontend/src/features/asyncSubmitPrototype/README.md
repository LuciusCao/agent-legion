# M44 原型：大批量添加条目 → 异步受理与进度（#1157 Phase 3）

**用途**：用户 UI 验收用原型（mission 硬规则：涉 UI 交互先原型确认再实现）。
纯静态 mock，不接后端。确认后本目录将被真实实现取代（届时整目录删除）。

## 查看方式

- 直接用浏览器打开 `prototype.html`；或
- `python3 -m http.server 8799` 后访问 `http://127.0.0.1:8799/prototype.html`。

顶部深色条是**原型控制台**（非产品 UI）：点击 ①~④c 跳转各状态；
③ 会自动播放进度推进直至完成；「进度指示位置」切换两种摆放方案对比。

## 场景设定

粘贴 ID 页签粘贴 2,400 个外部 ID（> 1,000 阈值，`BULK_RUN_SUBMIT_THRESHOLD`），
自动转异步受理。小批量（≤ 1,000 条）仍走同步快路径，交互与现状逐字节一致
（不在本原型演示）。

## 操作路径（真实产品中）

1. Studio → 添加条目 → 粘贴 ID，粘贴 2,400 个 ID。
2. 对话框内蓝色提示（替换 M40 的黄色「建议分批」提示）：超过阈值将转后台受理。
3. 点「创建运行」→ `POST /runs {mode:'async'}` 秒级返回 202：
   对话框立即关闭，左下 toast 给受理回执（运行编号），同时出现**持久**进度卡片。
4. 卡片轮询 `GET /runs/{id}`（`batch.processed_count` / `jobs_created`；
   跳过数 = 已处理 − 新建，与后端约定一致），进度条持续推进。
   进行中可「暂停 / 取消创建」（M43 的 pause/cancel 端点；只停后台创建，
   不动已建任务）。
5. 终态：
   - 完成：汇总「新建 X 个任务；Y 个已有任务自动跳过」+「查看任务」。
   - 部分失败（chunk 级容错）：失败数 + 原因摘要 +「重试失败条目」
     （重提同一运行，确定性 run id + 去重保证不重复建任务）。
   - 失败：错误信息 +「重试」。
   卡片在手动关闭或下次提交前一直可见（非瞬时 toast）。

## 待用户拍板的决策点

1. **进度指示位置**：方案 A 右下角浮动卡片（默认，跨页面可见）vs
   方案 B 任务列表页内横幅（不遮挡内容，但离开页面不可见）。原型可切换对比。
2. **进行中是否暴露「暂停 / 取消创建」**：M43 端点已就绪；若觉得 Studio 用户
   不需要，可只展示进度不提供控制。
3. **受理 toast 文案**与对话框内异步提示文案的措辞。
